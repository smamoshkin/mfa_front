# AGENTS.md — WB Analytics Dashboard

## Обзор проекта

**WB Analytics Dashboard** — это фронтенд-приложение для анализа финансовой отчетности селлеров на маркетплейсе Wildberries. Приложение предоставляет возможности управления товарами, просмотра аналитики рентабельности, управления налоговыми ставками и синхронизации данных с API Wildberries.

## Технологический стек

### Основные технологии
- **React 19** — библиотека UI
- **TypeScript ~5.9.3** — типизация
- **Vite 7.2** — сборщик и dev-сервер
- **Tailwind CSS 4.1** — CSS-фреймворк
- **React Router DOM 7** — маршрутизация

### Библиотеки
- **Zustand 5** — управление состоянием (с persist middleware для localStorage)
- **Axios 1.13** — HTTP-клиент с интерцепторами
- **React Hook Form 7** + **Zod 4** — валидация форм
- **Recharts 3** — графики и диаграммы
- **React Hot Toast 2** — уведомления (toast)
- **Lucide React** — иконки
- **date-fns 4** — работа с датами
- **TanStack React Table 8** — таблицы

## Архитектура

### Аутентификация
- **JWT-токены** хранятся в `localStorage` (ключи: `access_token`, `refresh_token`)
- **authStore** (Zustand + persist) хранит `user`, `token`, `isLoading`, `error`
- **axiosClient** автоматически добавляет `Authorization: Bearer <token>` к каждому запросу
- При **401** — попытка refresh (заглушена), затем редирект на `/login`
- **Маршруты** защищены через компонент `PrivateRoute` (проверяет наличие `token`)
- Публичный маршрут `PublicRoute` — только для неавторизованных (Login)

### API-слой
Все API-вызовы организованы в модули:

| Модуль | Базовый URL | Описание |
|--------|-------------|----------|
| `authApi` | `/auth/*`, `/tenants/*` | Логин, регистрация, профиль |
| `productsApi` | `/products/*`, `/product-costs/*` | CRUD товаров и себестоимости |
| `analyticsApi` | `/analytics/*`, `/supplier-reports/*` | Рентабельность, экспорт |
| `taxApi` | `/tax-rates/*` | Налоговые ставки |
| `syncApi` | `/sync/*` | Фоновые задачи синхронизации |

> **Важно:** `dashboardApi` (`/dashboard/*`, `/sync/wb/`) в таблицу выше не включён — это мёртвый код: страница `Dashboard.tsx`, единственный потребитель модуля, удалена из проекта, роут `/dashboard` тоже отсутствует. Модуль по-прежнему возвращает захардкоженные моковые данные (реальные запросы закомментированы), но это уже не актуально, пока страницы нет. См. "Рекомендации для дальнейшей разработки".

Поддерживает сортировку по клику на заголовок и фильтр по каждой колонке (текстовый для чисел, select A/B/C для категорий).

### ABC-категоризация и оборачиваемость

В `Analytics.tsx` реализована ABC-категоризация товаров (функции `getMarginCategory`, `getTurnoverCategory`, `getAbcCategory`, `withAbcCategories`):

- **Категория по марже** считается честно — по накопительному вкладу в общую маржу (A — первые 80% кумулятивной маржи, B — следующие 15%, C — остальное).
- **Категория по оборачиваемости** считается по реальным данным с бэка. Эндпоинт `/analytics/rentability` теперь возвращает поле `turnover_days` в каждом объекте `products[]` (дни запаса: остаток на складе ÷ среднедневные продажи за выбранный период). Тип `RentabilityProduct` (`src/types/analytics.ts`) содержит обязательное поле `turnover_days: number`. `withAbcCategories` берёт его напрямую (`const turnoverDays = product.turnover_days`), без заглушек. Пороги категорий: `<=0` → C (нет данных/остатка), `<=30` → A, `<=60` → B, `>60` → C.
- **Общая категория** — матрица маржа × оборачиваемость (обе оси сильные — A, обе слабые — C, смешанные — B). Теперь, когда оборачиваемость не захардкожена, общая категория A снова достижима у товаров, сильных по обеим осям.
- В таблице «Статистика по товарам» значение оборачиваемости выводится округлённым до одного знака (`turnoverDays.toFixed(1)`), сортировка и фильтр колонки работают по точному числу.
